00 · Overview

HTML publishing

Turn a Python model into a self-contained page whose JavaScript re-solves in the browser.

The vorp/ models are pure logic — they print tables and write JSON. But a table can't show that the same player is worth different amounts to different seats, or that one sale reprices the whole board. So this layer ships the model's inputs into an HTML template whose script re-solves live.

Every page is exported two ways at once: a standalone pages/ file that opens straight off disk, and an optional gitignored artifacts/ fragment handed to the publishing host.

Full map: docs/spec/publishing/index.md.
01 · The exporter

HTML export pipeline

One page body, two destinations that want opposite things — so it is written twice, differing only by a skeleton.

write_pair takes a finished fragment string and emits both: the fragment verbatim to artifacts/ (gitignored) for a host that supplies its own <html>/<head>/<body>, and a copy wrapped in LOCAL_HTML_SKELETON to pages/ so a file:// URL gets the doctype it needs. The page body is byte-for-byte identical. The smaller write_local writes just the standalone page for models that publish no Artifact.

The whole concern is keeping the browser port faithful to Python. build_seat_value.py --verify re-solves every preset through the real model and prints the canonical numbers the page's JS must reproduce.

Spec docs/spec/publishing/01-html-export-pipeline.md.

What the spec pins down

  • ✓ The standalone page renders in standards mode from a file:// URL — the copy opened on a phone.
  • ✗ --verify re-solves the presets in Python and prints them; it does not itself diff against the shipped JavaScript. A genuine JS/Python divergence is caught by eye, not an exit code.
02 · The demo surface

Auction-drift demo

Four scripted mispricings, replayed pick by pick, folded into one tabbed page — because a static table can't show a sale move the board.

draft_demo.py replays a fixed sale order under four rules — fair-market, bargain-run, panic-run, position-runs — repricing everything left through price_board after each pick, and writes one JSON timeline per scenario.

build_draft_demo.py folds those four JSONs into pages/draft-demo-2026.html without re-solving. It lifts the style, markup, and render script out of the template at build time, slicing at exactly-once anchors — any other count raises SystemExit. And it hoists the shared opening board out of the four payloads, storing the 192-row list once so the merged page stays near single-scenario size.
