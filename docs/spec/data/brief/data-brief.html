00 · Overview

The data pipeline

Every dollar and every VORP figure rests on two CSVs — build them first, or there is nothing to price.

Two TypeScript exports fetch live feeds, join a hand-scraped snapshot, and write flat CSVs into data/. They answer to different sources and different failure modes, so they stay apart: the authoritative one whose output gets priced, and the corroborating one that sanity-checks it.

projections-{season}.csv is the load-bearing table the VORP engine reads; boberto-{season}.csv is a second opinion plus a real auction market. Keeping the pricing input off the second feed means it never depends on that feed's match quality.

Full map: docs/spec/data/index.md.
01 · Projections export

Projections export

One row per draftable player, fusing the Sleeper dump and projections with the hand-scraped board into the single number everything gets priced on.

export-projections.ts fetches the Sleeper player dump, the season-total projection, and weeks-1–3 (summed into their own coverage column), then joins sleeper-board-{season}.csv on player_id. Each row emits one season_pts_half_ppr with a pts_source flag — board when the scrape carried a PTS for that player, api when it fell back to the season endpoint, empty when neither had a number (dropped downstream, never a phantom zero).

The board wins because its PTS is the same snapshot that produced its $ and rank — mixing in the API number would leave dollars and points describing two different snapshots.

Spec docs/spec/data/01-projections-export.md.

What the spec pins down

  • ✓ The board's $/rank/points stay one consistent snapshot; API points only fill players the board is missing.
  • ✓ API halves re-fetch cache-busted each run; the board CSV is a point-in-time scrape with no API behind it.
  • ✗ sleeper_proj_dollar is not API-available — it is client-side only and must be hand-scraped, which is why the board CSV is committed.
02 · The Boberto twin

The Boberto twin

An independent projection and a real auction market, recomputed under this repo's own half-PPR rules and matched back onto Sleeper ids — no invented matches.

export-boberto.ts pulls FantasyPros projections and market AAV (ESPN, NFFC, Yahoo) from boberto.app, recomputes half-PPR from the raw stat line rather than trusting a black-box total, and joins each row to a Sleeper player_id. Matching is hard because the feed disagrees on nicknames, team abbreviations, position, and defense naming.

normalizeName strips punctuation and suffixes; NAME_ALIASES merges known spellings; matchSleeperPlayer resolves DEF by team abbreviation, then exact name+position, then a name-only fallback, breaking ties on team and active status.

Spec docs/spec/data/02-boberto-twin.md.

What the spec pins down

  • ✓ Aliases run over the Sleeper side of the index too, so they can only merge two spellings of a real player — never invent a match.
  • ✗ A projection that fails to match is emitted with a blank player_id and listed for hand-curation; an unmatched AAV row is dropped.
